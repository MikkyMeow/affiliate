# Audit Logs

Статус: draft

## Назначение

В этом разделе администратор смотрит журнал аудита: кто, когда и что именно сделал в админской части.

## Где находится

Админ-панель → Логи

## Что такое аудит

Аудит — это журнал системно важных действий.

Он нужен, чтобы:
- разбирать спорные ситуации;
- проверять, кто изменил данные;
- видеть время изменений;
- отслеживать ручные операции.

## Какие действия попадают в аудит

По проектным правилам аудит покрывает критичные действия, в том числе:
- создание и изменение менеджеров;
- назначение менеджеров партнёрам и рекламодателям;
- создание рекламодателей;
- изменения офферов и целей;
- изменения доступов к офферам;
- скрытие оффера от партнёра;
- изменение статусов конверсий;
- корректировки через batch;
- действия с анкетами;
- тесты postback и другие критичные операции.

## Что видит администратор

На странице подтверждены:
- таблица audit logs;
- только режим просмотра;
- фильтры по search, action, entity type, entity ID, actor ID, date from, date to;
- флаг `errorOnly`;
- пагинация.

## Фильтры

В журнале подтверждены фильтры:
- search;
- action;
- entity type;
- entity ID;
- actor ID;
- date from;
- date to;
- только ошибки.

## Когда смотреть аудит

Открывайте аудит, когда нужно понять:
- кто изменил оффер;
- кто поменял статус конверсии;
- кто открыл доступ партнёру;
- кто импортировал корректировки;
- когда именно было выполнено действие.

## Как читать запись аудита

При чтении записи полезно смотреть в таком порядке:

1. Время события.
2. Кто выполнил действие.
3. Какое action записано.
4. К какой сущности относится запись.
5. Есть ли признак ошибки.

**Результат:** вы понимаете не только факт изменения, но и его контекст.

## Основные действия

### Найти, кто изменил объект

1. Откройте раздел `Логи`.
2. Укажите `entity type` и `entity ID`, если они известны.
3. При необходимости добавьте период.

**Результат:** в таблице останутся записи по нужной сущности.

### Найти все ошибки за период

1. Выберите диапазон дат.
2. Включите `errorOnly`.

**Результат:** вы увидите только проблемные события.

### Найти действия конкретного пользователя

1. Укажите `actor ID`.
2. При необходимости добавьте `action` или период.

**Результат:** можно проверить историю действий конкретного администратора или менеджера.

## Основные поля

| Поле | Что означает | Когда используется |
|---|---|---|
| Search | Свободный поиск по записям | Когда известна только часть данных |
| Action | Код действия | Когда нужно найти конкретный тип операции |
| Entity type | Тип сущности | Когда ищете изменения оффера, партнёра, конверсии и так далее |
| Entity ID | Идентификатор сущности | Для точечного поиска |
| Actor ID | Идентификатор пользователя, который сделал действие | Для проверки действий сотрудника |
| Date from / Date to | Период | Для поиска во времени |
| Error only | Только ошибочные записи | Для разбора сбоев |

## Статусы

Отдельных статусов записей аудита на экране не подтверждено, но есть фильтр по ошибочным событиям.

## Частые ошибки и ситуации

| Ситуация | Что проверить |
|---|---|
| Кто изменил оффер | Отфильтруйте по `entity type` оффера и его ID. |
| Кто изменил статус конверсии | Отфильтруйте по сущности конверсии и проверьте action изменения статуса. |
| Кто открыл доступ партнёру | Ищите записи по сущности оффера или access action. |
| Кто импортировал корректировки | Ищите записи по adjustment batch и по периоду. |
| Когда было выполнено действие | Используйте период и время записи в таблице. |

## Ожидаемый результат

После работы с разделом администратор должен:
- быстро восстанавливать историю критичных действий;
- находить автора изменений;
- использовать аудит как подтверждение в спорных ситуациях.
