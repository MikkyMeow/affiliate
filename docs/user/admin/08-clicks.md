# Clicks

Статус: draft

## Назначение

В этом разделе администратор смотрит все клики по системе. В интерфейсе этот раздел называется `Транзакции`, но речь идёт именно о click-событиях.

## Где находится

Админ-панель → Транзакции

## Что такое клик

Клик — это зарегистрированный переход по tracking-ссылке.

По клику администратор может проверить:
- какой партнёр привёл трафик;
- по какому офферу пришёл пользователь;
- какая страна и устройство определились;
- на какой URL ушёл редирект;
- был ли клик дублем;
- почему по нему могла не появиться конверсия.

## Что видит администратор

На странице подтверждены:
- таблица кликов;
- поиск;
- фильтры по датам, офферу, партнёру, рекламодателю, стране и redirect outcome;
- фильтры по `clickId`, `sub1-sub5`, `ip`;
- сортировка;
- пагинация;
- отметка manual для ручных кликов.

## Список кликов

В списке кликов подтверждены фильтры и поля, связанные с:
- датой;

- оффером;
- партнёром;
- рекламодателем;
- country;

## Основные действия

### Найти клик по click ID

1. Откройте раздел `Транзакции`.
2. В поле фильтра укажите `clickId`.
3. Примените фильтр.

**Результат:** вы увидите только нужный клик или поймёте, что его нет в системе.

### Проверить клики по партнёру и офферу

1. Выберите партнёра.
2. Выберите оффер.
3. Добавьте период, если нужно.

**Результат:** в списке останутся клики только по этой связке.

### Проверить, почему редирект был не на target URL

1. Найдите нужный клик.
2. Проверьте страну и redirect outcome.
3. Сопоставьте данные с GEO-правилами оффера.

**Результат:** можно понять, был ли fallback, блокировка или обычный редирект.

## Click ID

`Click ID` — главный идентификатор клика.

Он нужен:
- для поиска клика в интерфейсе;
- для сопоставления с postback;
- для разбирательства по конкретной конверсии.

## Canonical Click ID

В проекте поддерживается canonical click ID.

Практически это нужно для сценариев с дублями:
- один клик может считаться основным;
- дубли могут ссылаться на канонический клик.

## Дедупликация

Клики могут проходить через дедупликацию.

По проекту подтверждены поля и логика:
- `is_duplicate`;
- `duplicate_of_click_id`;
- `dedupe_fingerprint`.

Если оффер запрещает дубли или ограничивает окно дублей, часть кликов может быть отмечена как дубли.

## Country

Country используется для:
- GEO-правил;
- проверки redirect outcome;
- поиска проблем с трафиком по странам.

## Redirect URL

Redirect URL помогает понять, куда реально ушёл пользователь после клика.

Если redirect не совпадает с ожидаемым target URL, проверьте:
- GEO;
- fallback;
- availability оффера;
- внутренние ограничения.

## Как диагностировать проблему по клику

1. Найдите клик по `clickId`, `sub`-меткам или периоду.
2. Проверьте оффер, партнёра и страну.
3. Посмотрите redirect outcome и redirect URL.
4. Если нужна конверсия, найдите её по `clickId` в разделе конверсий.
5. Если конверсии нет, проверьте postback и цель оффера.

**Результат:** администратор понимает, на каком этапе цепочка оборвалась.

## Статусы

Отдельные статусы клика как общего workflow в интерфейсе не подтверждены.

Но есть `redirectOutcome`, а для manual clicks используется отдельная отметка `Manual`.

## Частые ошибки и ситуации

| Ситуация | Что проверить |
|---|---|
| Клик не появился | Проверьте tracking-ссылку, период фильтра и не ищете ли вы по неверному `clickId`. |
| Клик появился как дубль | Проверьте настройки дублей кликов у оффера и окно дедупликации. |
| Неверная страна | Проверьте поле Country в записи и сравните его с ожидаемым GEO. |
| Неверный redirect URL | Проверьте `targetUrl`, GEO-правила, fallback и redirect outcome. |
| По клику нет конверсии | Проверьте postback, цель оффера и наличие конверсии по `clickId`. |
| Postback не нашёл клик | Проверьте, что рекламодатель передал правильный `clickId` и что клик относится к тому же офферу. |
