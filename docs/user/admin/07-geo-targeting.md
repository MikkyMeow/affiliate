# Geo Targeting

Статус: draft

## Назначение

В этом разделе администратор настраивает, из каких стран разрешён или запрещён трафик по офферу, и как система должна вести себя при неподходящем GEO.

## Где находится

Админ-панель → Офферы → Карточка оффера → Geo Targeting

## Что видит администратор

В блоке GEO подтверждены:
- allow-список стран;
- deny-список стран;
- переключатель strict targeting;
- информация о fallback URL;
- кнопки добавления и удаления стран.

## Назначение гео-правил

GEO-правила нужны, чтобы:
- ограничить трафик только нужными странами;
- заблокировать отдельные страны;
- заранее контролировать, куда уйдёт клик при неподходящем GEO.

## Разрешённые страны

Разрешённые страны находятся в allow-списке.

Если страна есть в allow:
- трафик из неё разрешён;
- дальнейшее поведение зависит от остальных правил оффера.

## Fallback / Redirect

У оффера есть `fallbackUrl`, а также логика redirect outcome.

По проекту подтверждены такие outcomes:
- `allowed_target_redirect`;
- `fallback_redirect`;
- `internal_unavailable_redirect`.

Это значит:
- разрешённый трафик уходит на целевой URL;
- неподходящий GEO может уйти на fallback;
- в части сценариев система может использовать внутренний unavailable redirect.

## Что происходит при запрещённом GEO

Это зависит от сочетания правил и strict targeting.

Практически администратор должен учитывать:
- deny-правило блокирует конкретную страну;
- при strict targeting система строже применяет ограничения;
- если используется fallback, пользователь может уйти не на основной URL.

## Как GEO влияет на клики

GEO влияет на:
- итоговый redirect URL;
- redirect outcome у клика;
- причину редиректа;
- диагностику, почему пользователь не попал на целевую страницу.

## Основные действия

### Добавить разрешённую страну

1. Откройте Geo Targeting в карточке оффера.
2. Выберите страну в allow-блоке.
3. Нажмите `Добавить`.

**Результат:** страна попадёт в список разрешённых.

### Добавить запрещённую страну

1. Откройте Geo Targeting.
2. Выберите страну в deny-блоке.
3. Нажмите `Добавить`.

**Результат:** страна попадёт в список запрещённых.

### Удалить страну из правила

1. Найдите страну в allow или deny списке.
2. Нажмите удаление рядом со страной.

**Результат:** правило для этой страны перестанет действовать.

### Включить или выключить strict targeting

1. Откройте блок GEO.
2. Переключите strict targeting.
3. Дождитесь сохранения.

**Результат:** оффер начнёт применять более строгую или более мягкую GEO-логику.

## Основные поля

| Поле | Что означает | Когда используется |
|---|---|---|
| Allow list | Разрешённые страны | Когда оффер должен работать только по части GEO |
| Deny list | Запрещённые страны | Когда нужно исключить отдельные страны |
| Strict targeting | Строгий режим применения GEO | Когда нельзя допускать трафик вне разрешённого набора |
| Fallback URL | Запасной URL | Когда неподходящий GEO не должен идти на основной лендинг |

## Фильтры и поиск

Отдельных фильтров в блоке GEO не подтверждено.

## Статусы

Отдельных статусов у GEO-правил в интерфейсе не подтверждено.

## Частые ошибки и ситуации

| Ситуация | Что проверить |
|---|---|
| Пользователь не попадает на целевой URL | Проверьте allow/deny правила, strict targeting и fallback URL. |
| Клик есть, но redirect другой | Проверьте `redirectOutcome` и GEO-правила этого оффера. |
| Страна определилась неверно | Проверьте страну в записи клика и сравните её с ожидаемым GEO пользователя. |
| Оффер работает только для части стран | Проверьте allow-список и deny-исключения. |

## Ожидаемый результат

После работы с разделом администратор должен:
- понимать, для каких стран доступен оффер;
- уметь объяснить, почему пользователь ушёл не на основной URL;
- быстро диагностировать проблемы по GEO через клики.
