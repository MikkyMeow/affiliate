# Offers

Статус: draft

## Назначение

В этом разделе администратор создаёт и редактирует офферы, привязывает их к рекламодателю, настраивает видимость, правила дублей кликов, цели, GEO и доступы для партнёров.

## Где находится

Админ-панель → Офферы

## Что такое оффер

Оффер — это предложение рекламодателя, по которому партнёры отправляют трафик и получают конверсии.

У оффера есть:
- название;
- рекламодатель;
- категория;
- целевой URL;
- статус;
- описание;
- режим видимости;
- настройки дублей кликов;
- цели;
- GEO-правила;
- постбэк-токен;
- доступы партнёров.

## Что видит администратор

В списке есть:
- таблица офферов;
- фильтр по режиму видимости;
- пагинация;
- ссылка на создание;
- действие открытия tracking-ссылки для партнёра.

В карточке оффера есть:
- общие настройки;
- блок рекламодателя;
- postback token;
- цели оффера;
- доступы партнёров;
- pending requests;
- список скрытых партнёров;
- GEO Targeting;
- статистика оффера.

## Список офферов

В списке подтверждены:
- public ID;
- название;
- категория;
- рекламодатель;
- target URL;
- статус;
- availability;
- даты создания и обновления.

## Основные действия

### Создать оффер

1. Откройте раздел `Офферы`.
2. Нажмите `Создать оффер`.
3. Заполните основные поля.
4. Сохраните форму.

**Результат:** новый оффер появится в списке.

### Редактировать оффер

1. Откройте карточку оффера.
2. Измените нужные поля.
3. Сохраните изменения.

**Результат:** настройки оффера обновятся без перехода в другие разделы.

### Сгенерировать tracking-ссылку

1. В списке офферов откройте действие генерации ссылки.
2. Выберите партнёра.
3. При необходимости заполните `sub1`.
4. Скопируйте ссылку.

**Результат:** у вас будет готовая tracking-ссылка для конкретного партнёра.

## Создание оффера

На форме создания подтверждены такие поля:
- название;
- рекламодатель;
- категория;
- целевой URL;
- описание;
- статус;
- разрешение дублей кликов;
- окно дублей, если дубли запрещены не полностью.

После создания оффер можно дополнительно настроить через карточку:
- цели;
- доступы;
- GEO;
- postback.

## Редактирование оффера

В карточке редактирования подтверждены:
- название;
- категория;
- target URL;
- статус;
- availability;
- описание;
- настройки дублей кликов;
- цели оффера;
- доступы партнёров;
- заявки на доступ;
- скрытие от партнёров;
- GEO-правила;
- постбэк-токен и примеры postback.

## Основные поля оффера

| Поле | Что означает | На что влияет |
|---|---|---|
| Название | Публичное название оффера | На отображение в списках и карточках |
| Рекламодатель | Владелец оффера | Определяет связь оффера с рекламодателем |
| Категория | Тип оффера | Помогает классифицировать и фильтровать офферы |
| Целевой URL | Куда пойдёт разрешённый трафик | Влияет на итоговый редирект после клика |
| Описание | Текст для партнёров и команды | Помогает понять условия оффера |
| Статус | `active` или `inactive` | Влияет на доступность оффера |
| Видимость / availability | `public`, `on_request`, `private` | Определяет, кто видит оффер |
| Allow duplicate clicks | Разрешать ли дубли кликов | Влияет на дедупликацию кликов |
| Duplicate click window | Окно дедупликации от 1 минуты до 30 дней | Влияет на определение дубля |
| Postback token | Токен оффера для postback | Используется рекламодателем при отправке конверсий |

## Статусы оффера

| Статус | Что означает |
|---|---|
| active | Оффер включён |
| inactive | Оффер выключен |

## Видимость оффера

По проекту подтверждены такие режимы:

| Режим | Что означает |
|---|---|
| public | Оффер виден всем партнёрам, если он не скрыт вручную |
| on_request | Оффер виден партнёрам, но без полного доступа партнёр работает через заявку |
| private | Оффер скрыт, пока доступ не выдан вручную |

## Настройки дублей кликов

Оффер поддерживает два варианта:
- дубли разрешены;
- дубли ограничиваются окном дедупликации.

Если дубли не разрешены полностью, администратор задаёт окно от 1 минуты до 30 дней.

Это влияет на то, будет ли новый клик считаться самостоятельным или дублем существующего клика.

## Доступность для партнёров

Доступность зависит сразу от нескольких условий:
- статус оффера;
- availability;
- ручной доступ;
- скрытие оффера для конкретного партнёра;
- заявка на доступ по `on_request`.

Если партнёр скрыт вручную, скрытие имеет максимальный приоритет и перекрывает даже `public` и уже выданный доступ.

## Частые ошибки и ситуации

| Ситуация | Что проверить |
|---|---|
| Партнёр не видит оффер | Проверьте статус оффера, availability, ручной доступ и скрытие для партнёра. |
| Tracking-ссылка ведёт не туда | Проверьте `targetUrl`, GEO-правила и fallback-логику. |
| Клики не засчитываются | Проверьте, не срабатывает ли дедупликация и не блокирует ли оффер трафик по GEO. |
| Оффер выключен | Проверьте статус `inactive` в карточке оффера. |
| Оффер доступен не всем | Проверьте availability, pending requests, ручные доступы и hidden override. |

## Ожидаемый результат

После работы с разделом администратор должен:
- создать рабочий оффер;
- привязать его к рекламодателю;
- выдать доступ подходящим партнёрам;
- убедиться, что клики идут на правильный URL и конверсии могут быть приняты.
