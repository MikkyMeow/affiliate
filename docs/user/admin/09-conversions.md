# Conversions

Статус: draft

## Назначение

В этом разделе администратор смотрит конверсии, фильтрует их по статусам и суммам, меняет статус, проверяет историю статусов и ищет ошибки по click ID, цели или внешнему transaction ID.

## Где находится

Админ-панель → Конверсии

## Что такое конверсия

Конверсия — это результат по офферу, который система приняла через tracking или создала вручную через корректировки.

Конверсия может быть:
- обычной tracking-конверсией;
- manual-конверсией;
- test-конверсией, если использовался тестовый сценарий.

## Что видит администратор

На странице подтверждены:
- таблица конверсий;
- фильтры по периоду, офферу, цели, партнёру, рекламодателю;
- фильтры по статусу, source и test;
- фильтры по `clickId`, `conversionId`, `externalTransactionId`;
- фильтры по диапазонам revenue и payout;
- изменение статуса;
- раскрытие истории статусов;
- отметки `Manual` и `Test`.

## Список конверсий

В списке администратор работает с:
- датой создания и обновления;
- текущим статусом;
- source;
- test-меткой;
- click ID;
- offer, goal, affiliate, advertiser;
- revenue и payout.

## Основные действия

### Найти конверсию по click ID

1. Откройте раздел `Конверсии`.
2. Укажите `clickId` в фильтре.
3. Примените фильтр.

**Результат:** вы увидите конверсию по конкретному клику или поймёте, что она не была создана.

### Отфильтровать pending конверсии

1. Выберите статус `pending`.
2. При необходимости ограничьте период, оффер или партнёра.

**Результат:** в списке останутся только конверсии, ожидающие решения.

### Изменить статус конверсии

1. Найдите нужную конверсию.
2. Выберите новый статус.
3. Подтвердите изменение.

**Результат:** статус обновится, а изменение попадёт в историю и аудит.

### Посмотреть историю статусов

1. Раскройте нужную конверсию.
2. Откройте блок истории.
3. Просмотрите последовательность изменений.

**Результат:** вы увидите, кто и когда менял статус, а также переходы между статусами.

## Основные поля конверсии

| Поле | Что означает | Когда используется |
|---|---|---|
| Conversion ID | Идентификатор конверсии | Для поиска конкретной записи |
| Click ID | Идентификатор связанного клика | Для проверки цепочки click → conversion |
| Offer | Оффер конверсии | Для диагностики оффера |
| Goal | Цель оффера | Для проверки postback и ставок |
| Affiliate | Партнёр | Для проверки трафика партнёра |
| Advertiser | Рекламодатель | Для сверки с рекламодателем |
| Status | Текущий статус конверсии | Для финансового и операционного контроля |
| Source | `tracking` или `manual` | Для понимания происхождения записи |
| Is test | Тестовая ли запись | Чтобы не путать тесты с боевыми данными |
| Revenue | Доход по конверсии | Для контроля денег |
| Payout | Выплата по конверсии | Для контроля выплат |
| External Transaction ID | Внешний идентификатор рекламодателя | Для сверки с внешней системой |

## Статусы конверсий

| Статус | Что означает |
|---|---|
| pending | Конверсия принята, но ещё не подтверждена |
| approved | Конверсия подтверждена и участвует в confirmed money |
| rejected | Конверсия отклонена |
| cancelled | Конверсия отменена. Статус поддерживается проектом. |

## Связь с кликом

Tracking-конверсия обычно связана с click ID.

Это позволяет:
- искать конверсию по клику;
- проверять, был ли найден исходный клик;
- разбирать проблему “клик есть, конверсии нет”.

Для manual-конверсий click ID может отсутствовать.

## Цели и суммы

Цель конверсии определяет:
- какая цель засчиталась;
- какой revenue попал в запись;
- какой payout попал в запись;
- была ли применена индивидуальная ставка партнёра.

## Изменение статусов

Из интерфейса подтверждено изменение статусов конверсий.

Используйте его, когда нужно:
- перевести `pending` в `approved`;
- отклонить ошибочную конверсию;
- отменить manual-конверсию, если это поддерживается бизнес-процессом.

## История статусов

Для конверсий подтверждена загрузка истории статусов.

История полезна, когда нужно понять:
- какой статус был изначально;
- кто и когда его поменял;
- почему статистика изменилась после модерации.

## Ручные корректировки

Часть конверсий может иметь source `manual`.

Такие записи создаются через корректировки и тоже участвуют в статистике, если их статус это позволяет.

## Фильтры и поиск

Подтверждены фильтры:
- поиск;
- `dateFrom`, `dateTo`;
- `offerId`;
- `goalId`;
- `affiliateId`;
- `advertiserId`;
- `status`;
- `source`;
- `isTest`;
- `clickId`;
- `conversionId`;
- `externalTransactionId`;
- `revenueMin`, `revenueMax`;
- `payoutMin`, `payoutMax`;
- сортировка;
- размер страницы.

## Частые ошибки и ситуации

| Ситуация | Что проверить |
|---|---|
| Конверсия не появилась | Проверьте postback, правильный `clickId`, цель оффера и период фильтра. |
| Конверсия pending | Проверьте, не требуется ли подтверждение от рекламодателя или ручная модерация. |
| Конверсия rejected | Проверьте историю статусов и причину отклонения в связанных логах и процессах. TODO: уточнить, показывается ли причина отклонения прямо в таблице. |
| Сумма не совпадает | Проверьте цель, revenue, payout и индивидуальную ставку партнёра. |
| Цель не найдена | Проверьте, передан ли правильный `goalId` и принадлежит ли он этому офферу. |
| Клик не найден | Проверьте корректность `clickId` и относится ли он к этому же офферу. |
| Нужно изменить статус | Используйте статусное действие в строке конверсии и проверьте историю после изменения. |

## Ожидаемый результат

После работы с разделом администратор должен:
- находить любую конверсию по идентификаторам;
- понимать, как она связана с кликом и целью;
- корректно менять статусы;
- видеть, как статус влияет на статистику и деньги.
