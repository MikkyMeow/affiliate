# Карточка оффера

Статус: draft

## Назначение

Карточка оффера нужна, чтобы рекламодатель посмотрел детали конкретного оффера и сверил по нему статистику, статусы и goal-разрезы перед подключением или проверкой postback.

## Где находится

Кабинет рекламодателя → Офферы → Открыть оффер

## Что такое карточка оффера

Это детальная страница конкретного оффера. В текущей реализации она сочетает:

- базовую информацию по офферу;
- статус и revenue;
- ссылку на preview URL, если она указана;
- статистику по выбранному периоду;
- разрез по статусам;
- разрез по целям (`goal`).

## Что видит рекламодатель

- ID оффера;
- статус;
- категорию;
- revenue;
- дату создания;
- дату обновления;
- preview URL, если он заполнен;
- фильтр периода по датам;
- карточки метрик;
- таблицу по статусам;
- таблицу по целям.

## Основная информация

В блоке основной информации подтверждены следующие поля:

- `ID`;
- `Статус`;
- `Категория`;
- `Revenue`;
- `Создан`;
- `Обновлён`;
- `Превью / лендинг`.

Отдельного описания условий приёма трафика на этой странице в текущем интерфейсе не подтверждено.

## Цели

На карточке оффера есть таблица `Цели (goal)`. Она показывает goal-разрезы по статистике оффера.

Подтверждено, что в этом блоке показываются:

- название цели или `goalId`;
- число конверсий по этой цели.

Если по выбранному периоду goal-разрезов нет, система показывает пустое состояние.

Рекламодатель видит поле `Revenue`, а также финансовые значения в статистике оффера.

## Revenue и payout

На карточке оффера подтверждены:

- `Revenue` как часть основной информации по офферу;
- `Revenue` и `Payout` как показатели в статистическом блоке.

Важно:

- revenue и payout в статистическом блоке относятся к данным по выбранному периоду;
- поле `Revenue` в основной карточке оффера не заменяет финансовую сверку по конверсиям.

## Статистика по офферу

В разделе `Показатели по офферу` рекламодатель видит:

- клики;
- конверсии;
- approved;
- revenue;
- payout;
- pending.

Дополнительно доступны:

- фильтр `Дата от`;
- фильтр `Дата до`.

## Postback-настройки

Отдельного блока с postback URL, токеном или сигнатурой в карточке оффера рекламодателя сейчас не подтверждено.

Поэтому перед интеграцией постбека рекламодатель должен использовать данные, полученные от платформы или менеджера, и сверять их с этим оффером по:

- ID оффера;
- целям (`goal`);
- статусу оффера.

## Что проверить перед подключением postback

1. Откройте нужный оффер.
2. Проверьте, что оффер доступен и не возвращает сообщение о недоступности.
3. Сверьте `ID` оффера с тем оффером, для которого вы настраиваете postback.
4. Проверьте, что вы понимаете, какую цель нужно передавать в `goalId` или `goal_id`.
5. Сверьте expected revenue и payout по отчётам.
6. Убедитесь, что postback на вашей стороне будет отправляться только после целевого действия.

**Результат:** вы подключаете postback к правильному офферу и передаёте данные в корректную цель.

## Основные действия

### Открыть карточку оффера

1. Перейдите в раздел `Офферы`.
2. Найдите нужный оффер.
3. Нажмите `Открыть`.

**Результат:** откроется страница конкретного оффера.

### Проверить статистику по периоду

1. Откройте карточку оффера.
2. Заполните поля `Дата от` и `Дата до`, если нужен конкретный период.
3. Нажмите `Применить`.

**Результат:** показатели и таблицы обновятся по выбранному периоду.

### Проверить статусный разрез

1. Откройте блок `Статусы`.
2. Сравните число конверсий в `pending`, `approved`, `rejected` и других доступных статусах.
3. При необходимости откройте [Postback](./04-postbacks.md) для проверки причины расхождения.

**Результат:** вы понимаете, на каком этапе находятся конверсии по этому офферу.

### Проверить цели по офферу

1. Откройте блок `Цели (goal)`.
2. Сравните названия целей или `goalId`.
3. Сверьте, в какую цель должны попадать postback-события.

**Результат:** вы понимаете, какой goal использовать в postback.

## Основные поля

| Поле | Что означает | Когда используется |
|---|---|---|
| ID | Внутренний ID оффера | Для сверки между разделами и настройкой postback |
| Статус | Состояние оффера | Для проверки, активен ли оффер |
| Категория | Категория оффера | Для ориентира по типу оффера |
| Revenue | Базовый revenue оффера | Для общей сверки условий |
| Превью / лендинг | Ссылка на preview URL | Когда нужно открыть страницу оффера |
| Клики | Клики по офферу за период | Для проверки трафика |
| Конверсии | Все конверсии по офферу | Для проверки передачи результатов |
| Approved | Подтверждённые конверсии | Для контроля зачтённых действий |
| Payout | Выплата в статистике по периоду | Для финансовой сверки |

## Фильтры и поиск

Подтверждены:

- `Дата от`;
- `Дата до`.

Фильтра по goal, статусу или GEO внутри карточки оффера не подтверждено.

## Статусы

| Статус | Что означает |
|---|---|
| `pending` | Конверсия зафиксирована, но ещё не подтверждена |
| `approved` | Конверсия подтверждена |
| `rejected` | Конверсия отклонена |
| `cancelled` | TODO: уточнить, в каких сценариях статус показывается рекламодателю |

## Частые ошибки и ситуации

| Ситуация | Что проверить |
|---|---|
| Непонятно, какая цель передаётся в postback | Сверьте блок `Цели (goal)` и уточните нужный `goalId` |
| Ставка не совпадает с ожиданием | Сверьте revenue и payout по периоду; для точных условий может потребоваться уточнение |
| Revenue/payout отличаются | Проверьте период и статусный разрез, особенно `approved` и `pending` |
| Оффер неактивен | Проверьте поле `Статус` |
| Статистика по офферу не обновилась | Проверьте период и попробуйте сверить данные через [Статистика](./06-stats.md) |
| Postback отправляется не на тот оффер | Сверьте ID оффера и goal перед отправкой postback |

## Ожидаемый результат

После работы с карточкой оффера рекламодатель должен:

- понять, по какому офферу он работает;
- проверить статус оффера;
- сверить goal-разрезы;
- проверить статистику по периоду;
- убедиться, что postback будет отправляться в правильный оффер и правильную цель.
