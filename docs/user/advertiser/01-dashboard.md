# Dashboard

Статус: draft

## Назначение

Dashboard рекламодателя нужен для быстрого обзора текущей ситуации по его офферам: сколько было кликов, сколько пришло конверсий, сколько из них approved, pending и rejected, а также какой revenue и payout уже отражены в системе.

## Где находится

Кабинет рекламодателя → Обзор

## Что видит рекламодатель

- карточки с ключевыми метриками;
- блок с топом офферов;
- блок со статусами конверсий;
- ссылку на полный отчёт в разделе статистики;
- сообщения о загрузке, пустом периоде или ошибке загрузки.

## Основные метрики

| Метрика | Что означает | Как использовать |
|---|---|---|
| Клики | Все клики, пришедшие от партнёров | Помогает понять, есть ли входящий трафик |
| Лиды | Общее число конверсий | Показывает, передаются ли результаты обратно в платформу |
| Зачтено | Количество `approved` конверсий | Используется для контроля подтверждённых результатов |
| В рассмотрении | Количество `pending` конверсий | Показывает объём конверсий, которые ещё не дошли до финального статуса |
| Отклонено | Количество `rejected` конверсий | Помогает отслеживать долю отказов |
| Revenue (approved) | Подтверждённый revenue по `approved` конверсиям | Используется для оценки подтверждённых расходов |
| Payout (approved) | Подтверждённый payout по `approved` конверсиям | Помогает сверять выплаты партнёрам по подтверждённым конверсиям |

## Конверсии

В dashboard конверсии показаны в агрегированном виде:

- общее число лидов;
- число `approved`;
- число `pending`;
- число `rejected`.

Отдельной таблицы со списком конверсий на этом экране нет. Для детальной проверки лучше переходить в [Статистика](./06-stats.md) и [Postback](./04-postbacks.md).

## Расходы

На dashboard расходы отражаются через:

- `Revenue (approved)`;
- `Payout (approved)`.

Экран показывает именно сводку. Для сверки по периодам и статусам используйте [Финансы](./05-finance.md).

## Офферы

В блоке "Офферы" показывается срез по офферам за базовый период:

- название оффера;
- внутренний ID оффера;
- клики;
- лиды;
- revenue.

Если по офферу не было активности за период, он может не попасть в этот срез.

| Статус | Что означает |
|---|---|
| `pending` | Конверсия зафиксирована, но ещё не подтверждена |

## Как понять, что есть проблема

- Клики есть, а лидов нет: проверьте, что postback реально отправляется после целевого действия.
- В разделе dashboard есть лиды только в `pending`: проверьте, должен ли рекламодатель позже отправлять финальный статус `approved` или `rejected`.
- В блоке по статусам нет конверсий, хотя вы уже отправляли postback: откройте [Postback](./04-postbacks.md) и проверьте логи по `clickId`, HTTP-статусу и ошибкам.
- Revenue и payout равны нулю при наличии кликов: проверьте, появились ли `approved` конверсии.
- Данные по офферам пустые: проверьте период в [Статистика](./06-stats.md), потому что dashboard показывает только базовую сводку.

## Основные действия

### Быстро проверить, идёт ли трафик

1. Откройте dashboard рекламодателя.
2. Посмотрите карточку `Клики`.
3. Сравните её со значениями `Лиды` и `Зачтено`.

**Результат:** вы понимаете, есть ли входящий трафик и превращается ли он в конверсии.

### Проверить, есть ли зависшие конверсии

1. Откройте dashboard.
2. Найдите карточку `В рассмотрении`.
3. Сравните её со значением `Зачтено`.

**Результат:** вы видите, насколько большая часть конверсий ещё не дошла до финального статуса.

### Найти оффер с активностью

1. Пролистайте до блока `Офферы`.
2. Сравните офферы по кликам, лидам и revenue.
3. При необходимости перейдите в [Статистика](./06-stats.md) или [Офферы](./02-offers.md) для детальной проверки.

**Результат:** вы быстро понимаете, по каким офферам сейчас есть движение.

## Основные поля

| Поле | Что означает | Когда используется |
|---|---|---|
| Название оффера | Имя оффера в системе | Когда нужно понять, по какому офферу идёт активность |
| ID оффера | Внутренний идентификатор оффера | Когда нужно сверить оффер между разделами |
| Клики | Количество кликов по офферу | Для первичной оценки трафика |
| Лиды | Количество конверсий по офферу | Для проверки, работает ли возврат результатов |
| Revenue | Сумма revenue по данным dashboard | Для быстрой оценки расходов |

## Фильтры и поиск

На самом dashboard рекламодателя отдельные фильтры не подтверждены.

Для фильтрации по датам используйте [Статистика](./06-stats.md).

## Частые ошибки и ситуации

| Ситуация | Что проверить |
|---|---|
| Клики есть, но конверсий нет | Проверьте, отправляется ли postback после целевого действия |
| Postback отправляется, но конверсии не появляются | Проверьте логи в разделе [Postback](./04-postbacks.md), особенно `clickId`, статус и HTTP-код |
| Много конверсий в `pending` | Уточните, требуется ли потом отправлять финальный статус `approved` или `rejected` |
| Расходы отличаются от ожиданий | Сверьте approved revenue и approved payout в разделе [Финансы](./05-finance.md) |
| Данные за период выглядят неполными | Проверьте период в [Статистика](./06-stats.md), dashboard не даёт полного отчёта по датам |
| Статистика рекламодателя отличается от статистики администратора | Убедитесь, что сравнение идёт по одному и тому же периоду и по данным именно вашего рекламодателя |

## Ожидаемый результат

После работы с dashboard рекламодатель должен быстро понять:

- идёт ли трафик по его офферам;
- появляются ли конверсии в системе;
- в каком статусе находятся основные конверсии;
- есть ли признаки проблемы с postback;
- по каким офферам сейчас есть активность.
