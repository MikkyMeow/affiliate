# Финансы

Статус: draft

## Назначение

Раздел финансов нужен, чтобы рекламодатель сверял revenue, payout, число конверсий по статусам и понимал, как подтверждённые и неподтверждённые результаты влияют на суммы.

## Где находится

Кабинет рекламодателя → Финансы

## Что такое финансы

Это финансовая сводка по данным рекламодателя за выбранный период и, при необходимости, по конкретному офферу.

Раздел показывает:

- revenue по статусам;
- payout по статусам;
- число конверсий по статусам;
- разрез по офферам;
- разрез по статусам.

## Что видит рекламодатель

- фильтр `Дата от`;
- фильтр `Дата до`;
- поле `Offer ID`;
- карточки с суммами и количеством конверсий;
- таблицу `Разрез по офферам`;
- таблицу `Разрез по статусам`.

## Начисления

В текущем интерфейсе начисления показываются через revenue и payout по статусам конверсий.

Отдельного блока с бухгалтерскими начислениями, актами, счетами или документами не подтверждено.

## Revenue

В разделе подтверждены:

- `Revenue (pending)`;
- `Revenue (approved)`;
- `Revenue (rejected)`.

Также в разрезах показывается revenue:

- по офферам;
- по статусам.

## Payout

В разделе подтверждены:

- `Payout (pending)`;
- `Payout (approved)`;
- `Payout (rejected)`.

Также payout показан:

- по офферам;
- по статусам.

## Расходы

Для рекламодателя расходы в интерфейсе фактически читаются через revenue и payout по конверсиям.

Практически это означает:

- approved-данные используются для подтверждённых расходов;
- pending-данные показывают ещё не финализированные суммы;
- rejected-данные помогают понять, какие суммы не дошли до подтверждения.

## Сверка

Для сверки удобно использовать такой порядок:

1. Выберите период.
2. При необходимости укажите `Offer ID`.
3. Сравните summary-карточки с таблицами по офферам и статусам.
4. Сверьте цифры с разделом [Статистика](./06-stats.md).
5. Если есть спорные случаи, проверьте [Postback](./04-postbacks.md).

## Как статусы конверсий влияют на суммы

| Статус | Как влияет на суммы |
|---|---|
| `pending` | Показывает неподтверждённые revenue и payout |
| `approved` | Формирует подтверждённые revenue и payout |
| `rejected` | Показывает отклонённые значения и не относится к подтверждённым результатам |
| `cancelled` | TODO: уточнить, как именно должен трактоваться в пользовательской документации рекламодателя |

## Основные действия

### Посмотреть общую финансовую сводку

1. Откройте раздел `Финансы`.
2. Не задавайте фильтр по офферу, если нужна общая картина.
3. Смотрите summary-карточки по revenue, payout и конверсиям.

**Результат:** вы получаете общую финансовую картину по своему кабинету.

### Проверить суммы по конкретному офферу

1. Откройте раздел `Финансы`.
2. Введите `Offer ID`.
3. При необходимости задайте период и нажмите `Обновить`.

**Результат:** данные обновятся по выбранному офферу.

### Сверить суммы по статусам

1. Откройте блок `Разрез по статусам`.
2. Сравните revenue, payout и число конверсий по каждому статусу.
3. Сопоставьте данные с логикой вашего postback-процесса.

**Результат:** вы понимаете, какая часть сумм уже подтверждена, а какая ещё нет.

## Основные поля

| Поле | Что означает | Когда используется |
|---|---|---|
| Date from | Начало периода | Для выборки нужного диапазона |
| Date to | Конец периода | Для выборки нужного диапазона |
| Offer ID | ID конкретного оффера | Для сверки по одному офферу |
| Revenue (pending) | Неподтверждённый revenue | Для контроля ожидаемых сумм |
| Revenue (approved) | Подтверждённый revenue | Для контроля фактических сумм |
| Payout (approved) | Подтверждённый payout | Для сверки выплат по подтверждённым конверсиям |
| Approved конверсии | Число подтверждённых конверсий | Для связи финансов с конверсиями |

## Фильтры и периоды

Подтверждены:

- `Дата от`;
- `Дата до`;
- `Offer ID`.

Отдельных фильтров по статусу, goal или партнёру в разделе финансов рекламодателя не подтверждено.

## Статусы

| Статус | Что означает |
|---|---|
| `pending` | Конверсия ещё не подтверждена |
| `approved` | Конверсия подтверждена |
| `rejected` | Конверсия отклонена |
| `cancelled` | TODO: уточнить пользовательскую трактовку в финансовом разделе |

## Частые ошибки и ситуации

| Ситуация | Что проверить |
|---|---|
| Расходы не совпадают с ожиданием | Сверьте период, `Offer ID` и approved-значения |
| Pending-конверсии попали или не попали в расчёт | Смотрите отдельно pending revenue и pending payout |
| Rejected-конверсии не учитываются как ожидалось | Проверьте разрез по статусам и используемую логику сверки |
| Revenue отличается от payout | Это нормальная ситуация, если условия оффера и выплат разные |
| Статистика за период отличается от выгрузки | TODO: уточнить, поддерживается ли выгрузка; также проверьте одинаковый период и оффер |

## Ожидаемый результат

После работы с разделом финансов рекламодатель должен:

- видеть суммы по `pending`, `approved` и `rejected`;
- понимать связь между конверсиями и деньгами;
- сверять данные по конкретному офферу;
- находить расхождения до обращения в поддержку.
