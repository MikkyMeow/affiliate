## Не до конца оговорено

### Макросы

Макросы — это плейсхолдеры, которые рекламодатель или трекинговая система заменяет своими значениями.

Например:

```js id="bpxleo"
clickId: "{click_id}",
orderId: "{order_id}",
status: "{status}",
amount: "{amount}"
```

У разных рекламодателей они могут называться по-разному:

```txt id="q9ayuj"
{click_id}
{clickid}
{subid}
{transaction_id}
{order_id}
{lead_id}
```

Нужно будет решить, поддерживаем ли мы пока только обычные имена параметров или даём админу настраивать названия макросов.

### Разные версии постбэка

Я имел в виду разные шаблоны под разные события:

* lead;
* sale;
* registration;
* deposit;
* custom goal.

Сейчас можно сделать универсальный шаблон на цель. Это нормальный MVP.

## Лучшее техническое решение по связи с партнёром

Не создавать синтетический click без необходимости.

Для ручных конверсий лучше сделать так:

```txt id="w9g1fq"
conversion.partner_id
conversion.offer_id
conversion.goal_id
conversion.source = manual
conversion.click_id = null
conversion.manual_adjustment_batch_id = ...
```

То есть конверсия может быть:

* tracking-based: связана с click;
* manual: напрямую связана с partner/offer/goal.

Это чище, чем плодить фейковые клики, потому что фейковые клики потом будут портить CR и аналитику. А человечество и так уже достаточно испортило аналитику Excel-файлами.

Для ручных кликов:

```txt id="y4xnm6"
click.source = manual
click.partner_id
click.offer_id
click.goal_id nullable
```

Но ручные клики стоит грузить только если они реально оплачиваемые/нужны для статистики.
